# 卡牌工坊

## 打开工具

Windows 中双击项目根目录的 `启动卡牌工坊.cmd`，浏览器会自动打开 `http://127.0.0.1:3210`。需要电脑安装 Node.js 24 或以上；不需要安装额外 npm 依赖。关闭启动窗口即可停止工具。

其他系统可进入 `rhodes-pvp-v98` 后运行 `npm run cards`。

用户当前完整项目位置：`F:\NTCG\project`。这个目录用于编辑源码；`F:\NTCG` 中原有的 ZIP 和说明继续保留。

工具单独监听本机地址，不要把它部署到公网游戏服务器，也不需要开放 3210 端口。

## 日常使用

- 编辑已有卡：在左侧搜索 ID/名称/特征，修改表单，查看右侧预览后点击「校验并保存」。ID 不能直接改名；需要新编号时新建卡牌。
- 新卡＋卡图：点击「新建卡牌」，填写 ID、名称、类型、等级等，选择图片后保存。图片自动以 ID 命名并关联，不需要手改 JSON。
- 批量卡牌：点击「导入 JSON」，接受单张卡对象、卡牌对象数组，或 `{ "mainCards": [...], "baseCards": [...] }`。预览新增/更新清单后导入。默认不覆盖同 ID 卡，只有明确勾选才能更新。
- 批量卡图：把文件命名成 `SD01-0001.webp` 等，点击「批量导入卡图」选择多张。工具按 ID 匹配、校验内容格式并更新 image 字段。找不到 ID、重复 ID、格式错误时整批拒绝。
- 导出：右上角「导出卡池 JSON」导出当前卡牌与卡池版本；图片文件仍保存在项目目录，不嵌入这个 JSON。

JSON 中若引用尚不存在的图片，需先把 image 设为空并导入卡牌，然后批量导入图片；单卡表单可以一次保存卡牌和图片。

支持 PNG、JPEG、WebP，单张不超过8MB，整批请求不超过64MB。工具按文件内容识别实际格式，修正不一致的扩展名；不接受 SVG 或执行脚本。

## 规则与联机状态

卡面文字不是可执行的规则。新增带效果的卡、修改已有规则字段，会标记为「待接入」，服务器会拒绝含这些卡的联机卡组。后续需要实现/确认规则并补测试，再由开发者解除标记。

新增的普通基础无效果干员可以保存为已支持：类型为干员、基础干员、效果填写“无效果”或“无效果。”，不带特殊机制字段。只替换已有卡图不会把已实现的卡误标为待接入。

工具保留卡牌原有的额外字段，普通表单不直接编辑复杂机制字段；导入 JSON 时仍会校验关键字段类型。

## 保存与备份

保存位置为项目内：

```text
rhodes-pvp-v98/data/cards.json
rhodes-pvp-v98/data/base-cards.json
rhodes-pvp-v98/data/card-pool-version.json
rhodes-pvp-v98/public/images/cards/
```

每次写入前自动备份受影响文件到 `rhodes-pvp-v98/.card-manager/backups/`。备份不提交 GitHub。遇到同一文件被其他程序更新，工具会拒绝旧版本保存，刷新后再操作。

卡池数据与图片都纳入版本管理；导入后可让 Codex检查、测试并同步到 GitHub。工具本身不会保存 GitHub 凭证、自动推送或上传服务器。

## 同步到服务器

本地导入 → 检查待接入效果 → 运行 `npm test` → 提交并同步 GitHub → 备份线上版本 → 更新实际运行目录 `/opt/ntcg-offline/app` → 重启 `ntcg` 并验收。导入工具不是自动上线按钮。

已经关联的同名图片替换后可强制刷新；新增卡图关联、卡池数据及代码更新需要重启游戏服务。当前对局存在内存中，重启会中断对局。
