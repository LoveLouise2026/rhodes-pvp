## 每次修 Bug 的固定流程

1. 记录：卡组、回合、己方/对方场面、手牌（私下提供）、操作顺序、预期结果、实际结果。尽量提供双方截图或「联机操作」面板里的最近结算记录。
2. 先在本地复现，再加一条能覆盖实际问题的回归测试。规则问题改 `engine/rules.js`，界面问题改 `public/online-effects.js/css`；不要直接在服务器临时改规则。
3. 在 `rhodes-pvp-v98` 运行 `npm test`。验证修复和其他效果，再把改动提交到自己的 NTCG 仓库，标记本次版本。
4. 生成更新包。当前服务器已有 Linux 运行环境和 ws；普通代码/卡图更新不必重新下载 Docker 镜像。若依赖有变化，重新生成含依赖的离线包。
5. 先结束现有对局，再备份实际运行的 app 目录，应用更新，重启 `ntcg`。重启会中断并清空现有对局。
6. 检查本机与公网 `/health`、网页、双端建房，以及本次 Bug 的复现步骤。失败时恢复备份并重启。

需要代为上线时，提供临时 SSH 授权或在本机配置好的 Workbench 凭证；不在聊天里发送密码、AccessKey Secret 或私钥。之前部署用的临时 SSH 授权已经撤销。

## 巡林者部署夜刀的规则

夜刀上场后，仍需手牌里有一张可展示的「行动组 A4」干员，才有发动条件。刚被巡林者部署的夜刀已经在战场，不能再用它自己支付展示手牌的条件。

例如：巡林者部署夜刀后，手牌仍有杜林，可展示杜林抽牌；若最后两张 A4 是巡林者和夜刀、现在都上场，则无法发动。

本次本地补丁仅增加“手牌无合法展示对象”的本人可见提示，并验证上述两种连锁。没有修改卡牌规则，也尚未更新服务器。提示不会把手牌缺少 A4 的信息发给对手。

## 卡图怎么提供

可直接使用本地 [卡牌工坊](card-manager.md) 导入并预览，无须手改 image 字段。

建议按唯一 ID 命名，不按角色名命名，因为同名基础与精英化是不同卡：

```text
SD01-0001.webp   夜刀
SD01-0007.webp   阿米娅基础
SD01-0008.webp   阿米娅精英化
SD02-0007.webp   陈基础
SD02-0008.webp   陈精英化
```

可把图片压缩成 ZIP 发到聊天里，或在本地源码的 `rhodes-pvp-v98/public/images/cards/` 中加入图片后提交 GitHub。现有显示会把卡图视为含卡名、等级、效果等文字的完整卡面，优先使用完整卡面；WebP、PNG、JPG/JPEG 均可。

卡牌还需要对应的 image 字段，例如在 `data/cards.json` 中：

```json
"image": "/images/cards/SD01-0001.webp"
```

基地卡使用 `data/base-cards.json`。运行 `npm run validate:cards` 检查图片是否存在。单独把图片放上去不会自动关联到 image 为空的卡牌。

当前服务器线上图片目录为 `/opt/ntcg-offline/app/public/images/cards/`。如果只是替换已经关联的同名图片，上传后浏览器强制刷新即可；如果新增图片关联、修改 JSON 或修改效果，需要随更新包部署并重启服务，因为卡池数据在服务器启动时加载。没有修改 Node 依赖时，不需要重装运行环境。

Linux 文件名区分大小写：`SD01-0001.webp` 与 `sd01-0001.webp` 不同。更新源码包时应把卡图也放进版本管理或对应发布包，避免下一次上线覆盖掉服务器独有的图片。
