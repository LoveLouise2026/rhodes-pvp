# Bug 修复与卡图维护

## 每次修 Bug 的流程

1. 记录卡组、回合、双方场面、操作顺序、预期结果、实际结果。手牌只私下提供，尽量附双方截图及左侧「出牌记录」。
2. 先复现问题，再添加覆盖实际问题的回归测试。规则问题检查 `engine/rules.js`，交互问题检查 `public/online-effects.js` 和样式。
3. 运行 `npm test`，验证修复和已有规则都通过，再提交并同步 GitHub。
4. 检查本次改动与发布包一致，保留可恢复的旧版本，由维护者按本地发布说明应用更新。
5. 用两端新建房间验证本次问题；尤其检查效果选择、取消、刷新恢复及对方可见信息。

GitHub 同步与应用发布是两个步骤。具体发布记录由维护者在本地保管，不在本文列出。

## 巡林者部署夜刀

夜刀上场后，手牌里仍需有一张可展示的「行动组 A4」干员，才有发动条件。刚被巡林者部署的夜刀已经在战场，不能展示它自己。

例如：巡林者部署夜刀后，手牌仍有杜林，可以展示杜林抽牌；如果最后两张 A4 是巡林者和夜刀、现在都上场，就无法发动。

没有合法展示对象时，只向本人提示原因，不把手牌信息发给对手。回归测试覆盖了这两种连锁情况。

## 卡牌与卡图

推荐使用项目根目录的「启动卡牌工坊」导入与预览，具体见 [卡牌工坊说明](card-manager.md)。新卡效果需要另外实现，不能只填写卡面文字。

图片按唯一 ID 命名，因为同名基础和精英化干员是不同卡：

```text
SD01-0001.webp   夜刀
SD01-0007.webp   阿米娅基础
SD01-0008.webp   阿米娅精英化
SD02-0007.webp   陈基础
SD02-0008.webp   陈精英化
```

支持完整卡面 WebP、PNG、JPG/JPEG。图片文件和卡牌的 image 字段必须对应；工坊可自动命名和关联。手工编辑时运行 `npm run validate:cards` 检查图片。

卡图也要纳入版本管理或发布包。文件名应保持大小写一致，避免换环境后找不到图片。
